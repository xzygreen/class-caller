## 同根因的补充修复

- 定时任务 PATCH 只传递提交字段，在事务内与当前任务合并、完整校验。并发“停用”和“只改说明”不会重新启用任务；管理端删除也检查并发不存在的结果。见 `schedule-races.test.js`。
- 测试不再读取工作区真实 `students.json`。仓库重启测试先释放写锁，再重新打开。
- HTML 的版本化本地资源与 `package.json` 一并升级至 2.1.6。
- CI 加入可重复执行的浏览器与原生契约测试；部署分发更新后的隐私与许可文档。

## 明确边界

1. 单写者锁面向同一主机、本地文件系统和遵守该锁协议的进程，不是分布式锁。旧版运行进程不认识新锁，升级仍必须停服；未知锁所有者按拒绝处理，不能盲删活动锁。
2. 提交后显示动作是同步、尽力执行的内存副作用，不是持久化投递发件箱。进程在提交和显示之间崩溃仍可能漏显示；当前显示队列本来不跨重启恢复。失败不会伪称数据库回滚；操作日志会标记 `committed: true`。需要跨崩溃可靠投递时，应另行实现持久化待投递状态和幂等重放，而不是宣称本轮提供了 exactly-once。
3. 交叉编译和可执行解析器契约不等于真实 Windows 7 验证。窗口前置、任务计划、注册表、目标程序启动、WinHTTP/代理网络仍需在受支持 Windows 环境验收。
4. 清理主库不等于清理所有副本。自动备份、部署备份、预清理快照、外部备份和系统日志有独立生命周期。清理工具不提供备份删除操作，也不删除学生名单；正常的 14 份自动备份轮转仍可能淘汰旧副本。
5. 未执行线上部署、Nginx/systemd 重载、GitHub Release 上传或生产数据清理。
